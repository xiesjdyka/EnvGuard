# EnvGuard — 环境预警 + 手动紧急关闭

一个 Windows 便携工具：在新设备上**确认一次正确的环境作为基准**，选择需要保护的软件和日志文件；以后运行时持续比较环境，有变化时预警，需要时一键强制结束配置范围内的软件进程和专属服务。

**它是预警和人工应急工具，不是防火墙、网络隔离器或“防封号保证”。不自动阻止启动、不自动杀进程、不修改系统代理、不删除文件。**

## 下载与运行

从 [正式发布页](https://github.com/xiesjdyka/EnvGuard/releases/latest) 下载 `EnvGuard-windows-x64.zip`，解压后双击 `EnvGuard.exe`。无需安装额外脚本运行时。使用 Windows x64 和 .NET Framework 4.8；启动时需要确认管理员权限，让进程、专属服务检查和紧急关闭提前具备权限。

程序未进行商业代码签名。请核对仓库、发布来源和 `SHA256SUMS.txt`，不要运行来历不明的改包。若安全软件阻止运行，请先审查来源和代码，不要为了运行而关闭安全防护。

## 新电脑首次配置

1. **先自己准备正确环境**：连接你确认可靠的代理，设置正确时区、区域和所用浏览器语言。本工具不能证明当前代理可靠，也不会把错误环境自动“修成正确”。
2. **保护软件**：通过“选择 EXE”“正在运行的软件”或“已安装的软件包”添加一个或多个应用。不要选快捷方式、系统组件或整个用户目录。
3. **确认关闭范围**：仔细检查安装目录是否仅属于该软件。勾选专属目录后，目录里的后台进程也会纳入范围。专属 Windows 服务需要在列表中单独勾选；不需要的服务不要选。
4. **环境与日志**：填写本机 HTTP/mixed 代理端口（例如 `10808`）。仅支持本机 IPv4 HTTP/mixed 代理，不支持把远程 SOCKS 节点地址直接填进去。
5. 选择一个 `.jsonl` 日志文件。它持续追加，不会清空原有记录。可放在任意有写权限的本地文件夹；不要放进公开仓库。写入失败会明确预警，不能承诺在磁盘满、目录失去权限时仍成功留痕。
6. 可选：选择所用 Chrome 用户配置目录里的 `Preferences`，以及 v2rayN 的 `guiNConfig.json`。未选则不检查它们。不要选别的 Chrome 配置目录。
7. 点击“检测并生成快照”。两个独立 HTTPS 出口检查都必须成功且一致；如果填写了预期 IP，结果还必须与它一致。
8. **核对显示的 IP、代理监听程序、时区、日志位置和软件范围**，勾选确认，再“保存并开始监测”。保存前会再次检查，过时或变化的快照不能直接保存。

到另一台电脑只复制解压后的程序包，**不要直接照搬旧设备配置**。每台新电脑重新进行首次配置。程序配置绑定当前电脑名和 Windows 用户身份，发现不一致时要求重新配置。

## 日常怎么用

- 每次先打开 `EnvGuard.exe`，等主窗口显示“所选检查项与基准一致”，再自行使用保护的软件。
- 最小化后保留在系统托盘。关闭主窗口并确认退出，会停止预警，但**不会**结束保护软件。
- 环境异常时：查看具体原因；需要停止就点击红色“紧急关闭保护软件”。**直接强制结束，不等待保存工作，不再二次确认。**
- 点“知道了”只是关闭提示，不会停止软件。环境恢复后，提示保留原始原因和最新结果，日志记录恢复。
- 日志按钮定位到所选文件。“查看进程范围”列出当前能确认归属的存活进程。
- 有意更换代理、IP、应用版本或监测设置后，用“重新配置”重新核对。软件安装位置或服务版本变了，需要移除旧条目再重新选择软件、确认目录和勾选服务。重新配置和退出程序期间不提供监测。绝不静默更新基准。
- 旧的 Claude 专用预警工具与本工具是独立程序。迁移完成前可保留旧工具；同一时间两者都监测会产生两套提醒。

## 到底检查哪些环境

| 检查项 | 内容 / 限制 |
| --- | --- |
| 设备与用户 | 当前电脑名、Windows 用户 SID |
| 时区 | Windows 时区 ID、自动夏令时开关、时区规则；**不锁死时间、日期或当前 UTC 偏移** |
| 区域 | 用户 locale、日期时间格式、数字格式 |
| 系统代理 | 用户代理开关、地址、绕过项、PAC 地址、连接模式；这些设置不证明所有应用都使用代理 |
| 代理监听程序 | 本机端口、实际监听程序路径、SHA-256；重启但路径和身份相同不算改变 |
| 代理出口 | 两个 HTTPS 检测点均通过明确指定的代理访问，不回退直连 |
| Chrome（可选） | 已保存语言、相关 HKCU/HKLM WebRTC 和预加载策略；不是桌面软件本身的字体/语言证明 |
| v2rayN（可选） | **已保存**的节点 ID、路由 ID、TUN 开关；不能证明实时全部流量路径 |
| 软件身份 | 主程序文件校验；更新后要求重新确认范围 |

本地扫描约每 500ms 一轮。网络请求并行、每次最多 2.5 秒，完成后约 1 秒再检查。**单次检测超时先记录并复核，连续两轮未确认才预警；有效出口结果变成另一个 IP 则立即预警。**这是检测时限，不是零延迟防泄漏保证。磁盘读取、系统调度和权限会影响实际速度。

大型程序的哈希使用文件元数据缓存，每 10 秒以内重新校验；不是每半秒重复读取整个程序。日志异常会显示在窗口中并持续尝试恢复写入。

## “所有进程”保护范围和边界

纳入紧急关闭：

- 已确认主程序的匹配进程；
- 用户明确确认的专属目录中的非系统进程；
- 监测期间能用父子关系、启动时间和进程句柄确认的子孙进程，包括已观察到后成为孤儿的进程；
- 用户选择且路径、二进制身份匹配的专属 Windows 服务。

不会仅按进程名乱杀；每次结束前重新核对 PID、启动时间和路径，防止 PID 重用误伤其他软件。进程启动事件用于补充扫描；事件不可用会明确提醒。Windows 目录中的命令行例外仅限确切系统路径的 `cmd.exe` 和 Windows PowerShell，且必须已证明属于保护进程后代；不会按名字关闭整机所有终端。

**不能承诺任意软件的“相关进程一个不留”**：监测前已脱离父进程、观察前已结束的短命父进程、未知的外部工作进程、远程任务、其他用户的不可读进程、共享系统宿主和任意虚拟机/容器，都可能无法可靠归属。系统组件不会被广泛结束。服务存在运行中的外部依赖时拒绝扩大停止范围。不能读取身份、版本变化、权限不足或结束失败都会报告“未完全确认”，不伪装成成功。

Claude Cowork 有一个**窄范围、特定服务二进制版本审计过的 HCS 适配器**：仅当选择 `CoworkVMService`，且服务身份匹配已审计 SHA-256 时，才结束已识别的 Cowork 客体。规则曾针对 Claude MSIX `2.16120.0.0` 校验；未来版本不自动视为安全匹配。无法识别的新版本会报告虚拟机关闭未确认。不会停止 `vmcompute`、`vmms`、WSL 或不相关客体。

结果显示“配置范围内未发现残留”，**不是**“整台电脑所有相关任务必然结束”，也不是断网或禁止软件再次启动。软件再次手动开启仍可运行。

## 日志与隐私

配置默认保存在 `%LOCALAPPDATA%\EnvGuard\profiles\default.json`，不是 EXE 旁边。日志位置由你选择。

每行是一条 JSON：带本地时间、UTC、会话 ID、序号、事件类型和细节。记录监测启停、基准确认、网络未确认/异常、预警原因、恢复和紧急关闭请求/结果。**日志和配置可能包含 IP、设备/用户标识、软件路径、节点选择信息，分享前请脱敏。**不记录代理账号密码、完整节点连接配置或本地文件内容。无后台上传、分析统计或自动遥测。

网络检测会访问 `api.ipify.org` 和 `checkip.amazonaws.com`，对方正常可见代理出口 IP。点击检查更新才通过指定代理访问 GitHub API。更新页和日志文件由系统默认应用打开；打开网页不等于本工具为该浏览器隔离网络。

仓库与便携发布包**不包含任何个人配置和日志**；发布脚本仅打包 EXE、README、LICENSE。

## 更新与开源维护

- 程序“检查更新”查询配置中的 GitHub 仓库正式 Release。默认是 `xiesjdyka/EnvGuard`。
- 有新版本时可打开发布页下载。退出监测后替换解压的 EXE，重开；本地配置和日志保留。换新电脑仍须首次配置。
- **不自动下载执行代码、不静默热替换运行中的监测器**。更新过程有停止监测的窗口，请先暂停保护软件。
- 源码更改推送后 GitHub Actions 自动编译和自测；推送 `v*` 版本标签后自动发布便携包和 SHA-256 校验文件。这是持续发布，不是无人维护自动修好任何新版本的软件。

## 本地编译与测试

Windows x64 + .NET Framework 4.8 自带编译器即可。推荐 PowerShell 7，无需 NuGet 或远程构建依赖：

```powershell
pwsh -NoProfile -File .\Build.ps1 -Test -Package
```

输出在 `out`。测试仅使用自己创建的父/子/无关进程夹具和合成配置，不结束真实软件、不保存实际环境基准、不修改网络设置。界面检查图片在 `test-output`，不能拿图片中的合成数据当实际监测结果。

发布时先改 `Program.Version` 和程序集版本、更新变更记录，确认测试，再推送源码和标签（例如 `v1.0.1`）。不要把 `profiles`、`local-data`、日志、密钥或测试输出提交到仓库。

## 项目结构

`Profile.cs` 配置和追加日志；`EnvironmentChecker.cs` 基准与代理检测；`NativeProcesses.cs` 进程身份与归属；`MonitorEngine.cs` 预警策略与应急操作；`Forms.cs` 原生中文窗口；`CoworkNative.cs` / `CoworkAdapter.cs` 窄范围适配；`Tests.cs` 和 `tests/Fixture.cs` 自动测试。
